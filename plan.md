# LMX plan

**Authoritative plan.** Adopted 2026-09-06 by independent review of the three
candidate roadmaps (#64, #65, #66) after integration PR #63 merged into `main`
(`032c5cc`). This document supersedes all previous plans; the prior roadmap
remains readable at [`d18fefc:plan.md`](https://github.com/uwplasma/LMX/blob/d18fefce2eb241b4c8d8bc733e914e530e8ce4d4/plan.md)
and the candidate drafts in their closed PRs. It is written so that an
independent agent can execute it phase by phase without further context.

Change control (D22, ADR 0006): this file is the project logbook. It changes
with every merged batch and every review: Section 2 records the measured state,
Section 6 marks each step done with its PR, and Section 13 gains one row. A
decision changes only through a new ADR in `docs/adr/`. Each pull request
carries its own handoff (what, why, how verified, plan step, next step);
discussion stays in PRs and issues.

## 0. How to use this document

| If you are… | Read | Then |
|---|---|---|
| starting a phase | Section 1 (targets), Section 4 (decisions), the phase in Section 6, Section 12 (agent instructions) | open the phase's first PR |
| reviewing a PR | the phase's exit gates in Section 6 and the validation rows in Section 7 it claims | require the numbers, not "implemented" |
| deciding whether to change the numerics | Section 3 (what the literature says) and the relevant ADR in Section 4 | write a new ADR before coding |
| looking for the current state | Section 2.5 (latest measured state), then the order of work in Section 6 | update Section 2 with every merged batch |
| logging a merged batch or a review | Section 2 (state), the step's row in Section 6, Section 13 (log) | one plan PR per batch; its description is the handoff |

Terminology: *fully developed* = 2-D cross-section solves (Hartmann, Shercliff,
Hunt); *3-D core* = the extruded duct/pipe solver in spatially varying fields;
*Q2D* = the Sommeria–Moreau depth-averaged vorticity model; *B1/B2* = the ALEX
benchmarks of Smolentsev et al. (2015); *lane* = a code path that exists only to
serve one benchmark; *gate* = a measured condition with a stated tolerance.

## 1. Goals and measurable targets

| # | Goal (owner) | Target for release 2.0 |
|---|---|---|
| G1 | Physics of 3-D fields, Q2D and others, with engaging plots and movies | Seven examples, each producing a publication-quality figure; three movies (Q2D forced turbulence, 3-D fringing duct current loops, stellarator-coil-field channel); every figure regenerated by `scripts/make_showcase_figures.py` |
| G2 | Slim repository below 10 MB | Ordinary clone ≤ 5 MB (3.5 MB today); Git media ≤ 1 MB (WebP); movies and raw data as release assets |
| G3 | Minimise lines and files, maximise figures and performance | Package ≤ 9,000 source lines and ≤ 14 modules (17,954 / 26 on 2026-09-13, of which the new core is 2,833); tests ≤ 1.2× source lines; no lane that serves one benchmark |
| G4 | CPU and GPU, GPU much faster | **restated 2026-09-22 (D23)**: absolute throughput, milliseconds per step and nanoseconds per cell per step at 64³–256³, reported separately for the float64-accurate mode (mixed precision, D16) and for true float32, on named hardware with the matmul precision and host load recorded; the same-code CPU/GPU ratio is reported with its baseline named in the same sentence. Measured on one A4000 (#142): the 128³ core at 17.5 ms per step float64-accurate (8.4 ns per cell per step; 17.53 ms over 128³ cells) and 4.84 ms true float32, against 138 ms float64 on the 36-core host's same JAX code (7.85×); 256³ fits on one 16 GB card (166 ms mixed). The 2026-09-13 target of 10× in float64 on an A4000 is withdrawn: GA10x runs float64 at 1/64 of float32, which caps a fair single-card float64 speed-up near the memory-bandwidth ratio (1.5–3×). Target: the Phase 2b gains in Section 2.5's units |
| G12 | Fast, cheap derivatives (added 2026-09-22, D29) | a reverse-mode gradient of a steady objective ≤ 1.5× the warm forward solve, ≤ 1.1× where the objective is self-adjoint; zero recompilation across a sweep of field, drive, conductance or Ha on one mesh; cold compile of a steady solve ≤ 5 s in 2-D and ≤ 20 s in 3-D (24–31 s and 30–90 s on 2026-09-22); varying-field steady CG iterations within 3× of the uniform field-line counts at Ha 100–1000 (800–5,600 against 15–68 on 2026-09-22) |
| G5 | Parallelised with strong scaling | **not met, measured**: two A4000s run the Q2D solve to a bit-identical answer but at 0.25 efficiency in float64 and 0.14 in float32 at 2048², because the cards are PCIe-joined with no NVLink and the unaided partitioning of a 2-D transform all-gathers every step. Split from 2026-09-13: **G5a** ensembles across the two cards (Ha sweeps, design, gradient checks) at ≥ 0.9 efficiency; **G5b** spatial decomposition only where a run does not fit one card, or ≥ 0.6 measured at 256³ with an explicit slab (step 2.4b) |
| G6 | FreeMHD, OpenFOAM and other codes as inspiration | Ni et al. consistent-and-conservative scheme (FreeMHD, HIMAG, epotFoam, MHD-UCLA); CaNS / CaNS-EIGEN and Oceananigans for mixed transform–tridiagonal Poisson solves; Krasnov et al. 2023 for the thin wall inside a direct solver; jax-cfd solver architecture; jaxDecomp for distributed transforms |
| G7 | B1/B2 validation | **tiered (D20)**: ANL analytic fringe within 1 %; B2 axial pressure gradient within 5–10 % of experiment through the inertialess core-flow model with the measured field and the pressure-tap correction, transverse Δp by shape and sign; code-to-code (FreeMHD, core-flow model, 3-D core at moderate N) within 1–2 %; B1 through the core-flow model; a resolved 3-D B2 only as a cost-bounded cross-check |
| G8 | Retire experimental lanes | The B1/B2 and generic extruded lanes (6,002 lines) deleted from `main` after the new core carries the fully developed cases at parity (1.10b) and the fringing rows 6–7 (1.9); history kept at `lmx-b2-lane-v1` |
| G9 | Useful design results | A fully developed inverse-design example and a device-informed channel example with verified gradients |
| G10 | Thermal channel physics | Passive-scalar energy equation with conjugate walls on the new core, verified against laminar limits |
| G11 | Steady solves and adjoints at blanket Ha | Certified adjoints to Ha 1000 in the regression tier (today the tests stop at Ha 5 and the shipped tangent solve fails at Ha 300); a 3-D 128³ steady solve within 16 GB; Krylov iterations reported against Ha |

Non-goals before the release after 2.0: buoyancy, curved or mapped channels,
live coil or equilibrium derivatives, neutronics or structural coupling, free
surfaces, magnetic induction (Rm ≪ 1 stays), 3-D turbulent heat transfer.

## 3. What the research says

Five surveys were run for this plan (numerics at high Ha; JAX/GPU solver
architecture; Q2D turbulence; open validation data; presentation and process).
[V] = verified by reading the source; [M] = from memory. Full citations in
Section 11.

### 3.1 Numerics for high-Ha inductionless MHD

1. **Consistent-and-conservative scheme (Ni et al. 2007) [V].** Current as a
   face flux `J_n,f = −σ_f (φ_N − φ_P)/d_PN + σ_f (u_f × B_f)·n_f`; the potential
   Poisson equation assembled as the divergence of that same flux; the Lorentz
   force reconstructed by `(J×B)_c = (1/Ω) Σ_f J_n,f s_f (r_f − r_c) × B_f`.
   Implemented by HIMAG, MHD-UCLA, epotFoam, Blishchik 2021, Siriano 2024,
   Eardley-Brunt 2024, FreeMHD 2025. In the core `−∇p + J×B = 0` to O(Ha^-2), so
   any O(Δ) inconsistency between the two parts of J is amplified by Ha²; only
   this scheme reproduces Shercliff/Hunt at Ha 1000 (Ni Fig. 9).
2. **Staggered (MAC) variables** (Ni Part III) [V abstract]: face velocities are
   what `J_n,f` needs; no Rhie–Chow, no clipping.
3. **Thin conducting-wall condition** (Walker 1981; `j·n = ∇_τ·(c ∇_τ φ_w)`,
   `c = σ_w t_w/(σ a)`) [V]: valid for `t_w ≪ a/√Ha`, c ≪ 1; holds for B1
   (`t_w/a = 0.056`, c 0.027) and B2 (0.14, 0.07); how MHD-UCLA reaches Ha 15,000
   on a 99² stretched mesh (Smolentsev 2015 Table I). Requires its own thickness
   validity check (#65).
4. **Layer resolution** [V]: ≥ 6–8 cells across `a/Ha`, ≥ 10 across `a/√Ha`,
   geometric ratio ≤ 1.15, axial refinement across the fringe; ~120 cells across
   the half-width for B2, ~150 for B1.
5. **Stiffness** [V]: the velocity part of the Lorentz force is a damping with
   rate `σB²/ρ`; explicit treatment needs `Δt ∝ Ha^-2` (UKAEA: 5e-3 s at Ha 20 →
   1e-6 s at Ha 1000). Treat it linearly implicitly as a correction to the
   conservative face force, `F^{n+1} ≈ F^n_cons − σ(B²I − BBᵀ)(u^{n+1} − u^n)`,
   which vanishes at steady state; Crank–Nicolson diffusion.
6. **Steady solves are linear at high N** [V Planas/Badia]: matrix-free GMRES on
   the monolithic (u, p, φ) system with a block preconditioner (Stokes block +
   potential Laplacian); Newton–Krylov when inertia matters; pseudo-transient
   continuation only as a globaliser. Least-squares stationarity is not a zero
   PDE residual (#65).
7. **Fringing-field physics and observables** [V ANL/FPP/TM-228; HyPerComp 2008]:
   3-D pressure drop from axial current loops closing through side layers;
   observable `ΔP/(σ U B0² L)` between taps. ANL analytic case (square duct,
   `x0 = 3`, c = 0.02): total 0.0932 vs fully developed 0.0754. Dimensional B2:
   2a = 0.0878 m, t_w = 6.25 mm, σ_w = 1.51e6 S/m, B_max = 1.1 T, U = 0.337 m/s,
   Re = 15,574. B1: a = 0.0541 m, t_w = 3.01 mm, σ_w = 1.39e6 S/m, B_max = 2.08 T,
   U = 0.07 m/s, Re = 3,986.
8. **Field inputs** [V Votyakov 2009]: the ALEX profile was measured; use div- and
   curl-free analytic fringes so `B_x` is consistent with `B_y(x)`; run B2 with
   `B_y` only and with the solenoidal pair.
9. **Cylindrical operators** [V Verzicco–Orlandi; Oud 2016; #65]: transverse
   vector diffusion has the cross terms `Δu_r − u_r/r² − 2∂_θu_θ/r²` and
   `Δu_θ − u_θ/r² + 2∂_θu_r/r²`; use the `r·u_r` flux form on a staggered mesh;
   test smooth Cartesian modes, transverse translation, rigid rotation and an
   axis-crossing manufactured field before trusting a pipe result.

### 3.2 JAX and GPU solver architecture

1. **jax-cfd** [V source]: pytree containers with static grid/offset/BC metadata;
   pad-then-slice boundary conditions; fast-diagonalisation pressure solves
   (host-side `eigh`, tensor apply, RHS mean subtraction, nullspace cutoff);
   `lax.scan` as the only loop.
2. **JAX-Fluids 2.0** [V]: one-axis decomposition for two devices, `ppermute`
   halos, `jax.checkpoint` per step inside `scan`, float64 on GPU; fp32 2.5–3×
   faster than fp64 on GA102.
3. **jaxDecomp** [V]: pure-JAX slab/pencil FFTs and halo exchange; sharded
   `jnp.fft` also exists. Evaluate before writing our own.
4. **Fast diagonalisation on non-uniform tensor grids** [M]: two matmul passes
   per non-periodic axis; ~2e9 flops at 128³; trivial in fp32, compute-bound in
   fp64 on an A4000 (0.3 TFLOPS). DCT for uniform Neumann axes [V].
5. **Batched tridiagonal solves** [V]: `lax.linalg.tridiagonal_solve` is
   differentiable but calls cuSPARSE per system; measure against a vectorised
   Thomas sweep or SOLVAX.
6. **Implicit differentiation** [V]: `custom_root`/`custom_linear_solve`,
   optimistix `ImplicitAdjoint`, diffrax `RecursiveCheckpointAdjoint`; SOLVAX
   `root_solve`, `newton_krylov`, `checkpointed_fori_loop`. SOLVAX `root_solve`'s
   default tangent builds a dense Jacobian: supply matrix-free tangent/transpose
   solves (#65).
7. **Exponax/APEBench** [V]: ETDRK integrates the linear operator exactly; a
   linear drag is the Hartmann friction of the Q2D model; Kassam–Trefethen
   contour coefficients avoid cancellation.
8. **GPU practice** [V]: no per-step host sync; whole loop under `jit` + `scan`;
   `donate_argnums`; `block_until_ready` timing; persistent cache;
   `jax.profiler` for peak memory. RTX A4000: 448 GB/s, 16 GB, PCIe 4.0. The
   datasheet's 19.2 TFLOPS is a TensorFloat-32 tensor-core rating and its
   "fp64 = 1/64" is relative to that; measured true-float32 dense contractions
   beat float64 by 0.9× at 64³, 4.1× at 128³ and 12× at 192³ (Section 2.2).
9. **Expected performance** [M from bandwidth and JAX-Fluids]: fp64 one A4000
   ≈ 20–80 ms/step at 128³, 0.2–0.7 s/step at 256³; fp32 2–3× faster; 10–40× over
   a laptop CPU at ≥ 128³ but 2–5× at 64³; two-GPU efficiency 60–85 % at 256³,
   none at 64³. √-checkpointing 1,000 steps at 256³ fp64 exceeds 16 GB.
10. **Design throughput** (#65): independent batching (`vmap` over designs) before
    spatial sharding; logical CPU devices test partition parity, not scaling.

### 3.3 Q2D turbulence

1. **Model** [V Pothérat–Sommeria–Moreau 2000]: `∂_t u + u·∇u = −∇p/ρ + ν∇²u −
   (n/t_H) u + f`, `t_H = h²/(ν Ha_h)`, `n` = number of no-slip Hartmann walls
   (2 for a duct). Validity: Ha ≫ 1, N ≫ 1, laminar Hartmann layer (Re/Ha ≲ 380),
   scales `l_⊥ ≳ h N^-1/3`.
2. **Blanket regime** [V Smolentsev–Moreau 2006]: PbLi at h 0.1 m, B 5 T,
   U 0.1 m/s: Ha ≈ 1.2e4, Re ≈ 7e4, N ≈ 2e3, Re/Ha ≈ 6, t_H ≈ 5.6 s vs turnover
   1 s: friction-dominated Q2D is the blanket regime.
3. **Cases with literature numbers**: frozen decay (exact rescaling identity as
   ν → 0), electrically driven vortex lattice (Sommeria 1986: Kolmogorov constant
   3–7, condensation), Kolmogorov flow with drag (Kochkov 2021 reference fields),
   Tithof 2017 Kolmogorov-like flow with Rayleigh friction (Re_c = 7.60, q_c = 0.465
   for β = 1), MATUR-like shear layer, Q2D cylinder wake by penalisation (Hussam
   2011 tables).
4. **Numerics** [V Kassam–Trefethen]: ETDRK4, friction inside the exponential,
   2/3 dealiasing; cross-check against GeophysicalFlows.jl and Dedalus.
5. **Chaotic sensitivities** (#65, Blonigan 2014): AD through a short chaotic
   trajectory is not the sensitivity of a long-time average; optimise steady or
   checked finite-horizon objectives only.

1. **ALEX B1/B2** [V]: digitised curves "available upon request from the first

2. **FreeMHD** [V]: MIT; validated on Shercliff/Hunt (Ha ≤ 1000, 0.3–3.9 %) and
   KIT's fringing pipe (Ha 2000, N 200), not on ALEX; inputs on Zenodo 13964055.
3. **Other comparators** [V]: GridapMHD (monolithic FEM, Hunt example),
   epotFoam/mhdFoam in the same OpenFOAM image, UKAEA input files
   (DOI 10.14468/43ys-0z67), Dedalus and GeophysicalFlows.jl for Q2D.
4. **Thermal references** (#65) [V]: Lienhard §7.2 laminar limits (Nu = 48/11
   uniform flux, 3.66 uniform temperature); Mistrangelo et al. 2025 heated
   conducting duct (Ha 235); Gardner–Lykoudis 1971 and Sukoriansky 1989 show that
   field effects on heat transfer depend on arrangement; Pirozzoli 2023 low-Pr DNS.

### 3.6 What the 2026-09-13 review adds

Five further passes (fast solvers; JAX and devices; high-Ha numerics, walls
and validation data; a citation check; a source-level read of other codes).
Tags as above; [C] = checked by the citation pass.

1. **Mixed transform–tridiagonal direct solves** [V source]: CaNS applies FFT,
   DCT or DST per axis by boundary condition on the staggered grid (cell-centred
   NN → DCT-II/III, DD → DST-II/III, mixed → type IV; Schumann & Sweet 1988),
   with the discrete symbol `−4 sin²(θ/2)/Δ²` and a Thomas sweep on the one
   stretched axis; the GPU version runs one thread per column. CaNS-EIGEN
   (Costa et al. 2026, arXiv:2603.09528 [C]) symmetrises stretched axes with
   `M^½ T M^−½`, keeps the eigenbases as one GEMM per axis and mixes FFT and
   GEMM per axis; on one GPU the GEMM route costs 2.8× the FFT route for the
   Poisson solve and 1.8× for the step. Oceananigans' Fourier–tridiagonal solver
   allows exactly one stretched axis and batches the tridiagonal sweep over the
   Fourier modes; its CG solver for immersed boundaries is preconditioned by the
   FFT solve of the underlying regular grid. `jax.scipy.fft` has DCT type II
   only [C]; DST-II/IV and DCT-IV come from `rfft` with Makhoul twiddles.
   `jax.lax.linalg.tridiagonal_solve` batches over leading axes, is
   differentiable in its diagonals and calls cuSPARSE `gtsv2` on GPU [C].
2. **The thin wall inside a direct solver** [V slides; C]: Krasnov, Akhtari,
   Zikanov & Schumacher, JCP 474:111784 (2023) combine the Walker condition
   with the Poisson row of the wall cell and either modify the corner of the
   per-mode tridiagonal system (wall normal to the Thomas axis) or scale the
   tangential rows by `h₁/(h₁ − 2c_w)` and eigendecompose the modified
   one-dimensional matrix; the factor changes sign when `2c_w > h₁`, so the
   conditioning has to be checked before adopting the second form. Their
   `tanh` meshes reach aspect ratio 400 with nine points in the Hartmann layer
   at Ha 1200; everything is direct, nothing iterates. Buzbee, Dorr, George &
   Golub (1971) and Proskurowski & Widlund (1976) are the capacitance-matrix
   (Woodbury) form of the same idea [C].
3. **Mixed precision** [C]: Carson & Higham (SISC 2017, 2018) and Buttari et
   al. (2007, 2008) for refinement; GMRES-IR is 19–31 % faster than double
   GMRES at restart ≤ 200 and needs about three times the iterations at
   restart 400 on one GPU Laplacian (Loe et al. 2021). Defect correction of a
   direct solve, which is what D16 does, has no restart. No published paper
   does fp32 fast diagonalization with fp64 refinement for MHD; the SC'25
   Pareto framework (arXiv:2508.10202) is the template for reporting it.
4. **Precision on Ampere** [C]: JAX's `DEFAULT` matmul precision "uses
   tensorfloat32 if available"; `'highest'` (or `'float32'`) gives true
   float32; float64 is unaffected.
5. **High-Ha preconditioning is open** [C]: Ma, Hu, Hu & Xu (2016) and
   Laakmann, Farrell & Mitchell (2022) are resistive MHD with no Hartmann
   claim; Li, Ni & Zheng (2019) is inductionless and its Ha-robustness could
   not be confirmed. GridapMHD's block preconditioners use scaled mass
   matrices for the pressure and potential Schur complements with grad-div
   augmentation, and no iteration counts against Ha are published. The
   textbook answer to grid-aligned anisotropy is line relaxation in the thin
   direction with semicoarsening in the other (Trottenberg, Oosterlee &
   Schüller ch. 5). Pseudo-transient continuation with SER and the index-1
   DAE extension (Kelley & Keyes 1998; Coffey, Kelley & Keyes 2003) is the
   globaliser for a projection-constrained steady solve.
6. **SOLVAX 0.20.0 already ships** `iterative_refinement`, `as_low_precision`,
   `tridiagonal_solve`, `cyclic_tridiagonal_solve`, `solve_fourier_helmholtz`,
   `low_rank_corrected`, `gcrot`, `recycled_linear_solve`,
   `schur_complement_precond`, `semicoarsening_hierarchy`, `line_smoother`,
   `pseudo_transient_continuation` and `shard_batch` [V signatures]; LMX uses
   none of them. The work in Phases 1.11–1.12 and 1.7c–1.7e is adoption on
   LMX's operators, not new kernels.
7. **Walls in other codes** [V]: Ni et al. 2007, FreeMHD and FreeMHD2 mesh the
   wall as a solid region (FreeMHD has no thin-wall patch; Hunt walls are
   `c = 10` solids); Siriano et al. 2024 use seven cells across the wall and
   three outer iterations; Blishchik et al. 2021 a harmonic-mean face
   conductivity. No published corner rule for a discrete thin-wall operator
   exists; LMX states its own (charge conservation across the corner cell, as
   Hua et al. 1988 split the corner between the two sheets). Layer resolution
   used in practice: ≥ 4 Hartmann cells with insulating walls (Siriano; 6
   adopted), ≤ 2 suffice with conducting Hartmann walls, 5–10 per layer
   (Blishchik), 7 and 15 (UCLA), ≥ 10 (FreeMHD).
8. **Inertialess core-flow model** [V Bühler lecture, ANL reports]: in the
   core `∇p = j × B`, so `p` depends on the two coordinates normal to `B`,
   `j_∥` is linear and `φ` quadratic along field lines, and integrating mass
   conservation across the duct gives one elliptic 2-D equation
   `∇·[(h/B²)∇p] = F(φ_t, p, φ_b)` coupled to the thin-wall condition on each
   Hartmann wall: three coupled 2-D PDEs on the wall surface, the 3-D field
   reconstructed analytically. Hua et al. 1988 matched the ALEX axial
   pressure gradient with it at N 540 as well as at 1.26e5; Ni et al. 2007
   overlay it with their 3-D solution at Ha 1000–2000. Development lengths at
   Ha 1000 in a pipe: 9.5 radii upstream, 7.5 downstream. Bühler's CoreFlow is
   KIT-internal; no open implementation exists.
9. **B1/B2 as targets** [V ANL/OSTI reports]: no ALEX report tabulates
   pressure, potential, velocity or `B(x)`; the curves are figures, digitised
   on request from Smolentsev; Hua et al. 1988 is an inertialess SOR solution
   stopped at 0.1 % nodal change on an unreported grid; ALEX square-duct walls
   are 0.66 cm on 8.8 cm (`t_w/L ≈ 0.15`), the transverse tap runs through the
   side wall, and Reed & Picologlou (1989) report side-wall instabilities at
   `Re_cr` 2650–5100 for `2700 < M < 5400`, below B2's Re ≈ 15,600. Inertia
   is a few to about ten percent of the 3-D excess pressure drop by the
   Mistrangelo et al. 2021 fit `Δp∞ + αHa^−1/2 + βN^−1/3`. COMSOL and HIMAG
   match the B2 axial gradient and are "somewhat off" on the transverse Δp.
   A resolved 3-D B2 needs ≈ 160²×400 cells (≈ 50 M unknowns; a GMRES(50)
   basis alone is 21 GB). Only NaK properties (ANL/FPP/TM-237) are tabulated.
10. **Other data** [V/A]: Smolentsev 2015 Table I (Shercliff and Hunt `c` 0.01
    flow rates at Ha 500–15,000); Tao & Ni 2013/2015 thick and asymmetric
    walls; KIT MEKKA pipe entry (Bühler, Brinkmann & Mistrangelo 2020, Ha to
    5485, paywalled, FreeMHD's fringing validation); FZKA 7245 sudden expansion
    (Ha 1000–5800, c 0.028); Siriano et al. NF 2023 WCLL 3-D pressure drops
    tabulated with mesh sensitivity; Jiang & Smolentsev 2024 insulating fringing
    correlation (80 cases, R² 0.9967); ASME V&V 20 for the uncertainty
    statement (`u_val = √(u_num² + u_input² + u_D²)`).
11. **Q2D** [V]: PSM2000 adds `(n/(Ha N))[(7/36) D_ū ū + (1/8) ∂_t(ū·∇ū)]` with
    error `max(1/(Ha N), N^−2, Ha^−2)`; SM82 alone holds only for weak inertia
    (transient growth matches 3-D for `Re/Ha ≲ 33`, Cassells et al. 2019) and
    never for B1/B2. Kassam–Trefethen coefficients by the 32-point half-circle
    mean of radius 1.
12. **Distribution** [V source]: jaxDecomp is a `custom_partitioning` primitive
    with `all_to_all` transposes and `ppermute` halos (FFT only, no DCT);
    JAX-Fluids uses `pmap` with `ppermute` halos; jax-cfd forces the dense
    route for any non-periodic axis, the same weakness LMX has today.
13. **Field position** [C]: no other GPU or JAX inductionless duct code was
    found. FreeMHD2 (2026) and Vertex-CFD (2025, Kokkos, full induction) and
    NekRS MHD (full induction) are the nearest; JAX-AMG (2026) wraps AmgX as a
    differentiable primitive and is a possible comparator.
14. **Corrections to the earlier surveys** [C]: arXiv 2607.10983, 2606.09001
    and 2605.13378 are JAX geometric multigrid for particle-mesh, JAX-AMG and
    AD-based JFNK, not fast-Poisson papers; arXiv 2403.03899 is Akhtari et al.
    2024 (magnetoconvection), not the Krasnov solver paper.

### 3.7 What the 2026-09-22 review adds

Six surveys (axial boundary conditions, core-flow models, GPU performance,
Poisson algorithms, validation data and standards, experiments 2020–2026), two
further surveys on speed and derivative cost, and measurements on `385be68`.
Primary sources marked [P] were read in full for this review.

1. **ANL fringe reference** [P, ANL/FPP/TM-228, Hua, Walker, Picologlou & Reed,
   July 1988, OSTI 6789158]: `B_y = ½(1 − sin(πx/2x0))`, `x0 = 3`, `c_t = c_s =
   0.02`, aspect ratio 1, inertialess and inviscid core flow on `x ∈ [−6, 2]`,
   SOR stopped at 0.1 % change; "the overall pressure drop from x = −6 to x = 2
   given by the numerical analysis is 0.0932. A locally fully developed
   hypothesis yields a figure of 0.0754, an underestimate of the pressure drop
   of 19%." Locally fully developed treatment is safe when `ΔU/U0 < 10 %`, which
   needs a field-variation length of 20 half-widths or more. The report also
   carries the ALEX square-duct comparison (Figs 11–13).
2. **Core-flow equations** [TM-228 (4a)–(4c), (14); Molokov & Politis, FED 209
   (2024) 114688]: pressure is constant along field lines, which reduces the
   core to `∂x(β²∂x p) + [β² + (a²/3)β′²]∂zz p = β′∂z φ_t` with thin-wall
   charge conservation `c_t∇²φ_t = aβ′∂z p` and `c_s∇²φ_s = −β∂z p|_(z=−1)`,
   `β = 1/B`, plus the side-layer flux closure. Ha scales out when `c ≫ Ha⁻¹`;
   the side-layer closure needs `Ha^(−1/2) ≪ c_s ≪ 1`. The pipe needs only the
   first two equations (Roberts layers are passive). No open implementation
   exists (KIT CoreFlow and the ANL code are unreleased).
3. **Validity of the inertialess model** [Mistrangelo et al., FED 173 (2021)
   112795]: `Δp₃D = Δp₃D,∞ + 0.0934 Ha^−0.565 + 0.406 N^−0.337` for a conducting
   bend (c 0.052). The inertial term is 0.049 at ALEX B2 (N 540) and 0.018 at B1
   (N 10,700), the same order as the whole inviscid excess of the ANL fringe
   (0.0178). The TM-228 authors judged the model valid for N ≥ ~500 against ALEX;
   the community's code-versus-experiment tolerance is about 5 % (ANL/TD/CP-83923,
   1994). Thin-wall theory drops O(t_w²/a²), about 2 % for B2 (t_w/L ≈ 0.15);
   the thick-wall formulation is Bühler, FZKA 6066 (1998).
4. **Axial boundary conditions** [HIMAG (Rhodes, Smolentsev, Abdou, Phys.
   Fluids 30 (2018) 057101); FreeMHD (Phys. Plasmas 32 (2025) 013907, source);
   epotFoam; GridapMHD (source); Mistrangelo et al., Nucl. Fusion 65 (2025)
   116006, Table 4]: inlet velocity prescribed and pressure drop an output;
   outlet zero velocity gradient with `p = 0`; no normal current at both ends
   (`∂φ/∂n = (u×B)·n`, as FreeMHD's paper and HIMAG state; several codes use the
   cruder `∂φ/∂n = 0`); nobody in 3-D imposes the flow rate through a Lagrange
   multiplier. Buffers in practice: 15–20 half-widths upstream and 10–15
   downstream (ALEX comparisons −15a/+10a; Ni Part II −20a/+15a). The 2025
   benchmark found entrance and exit artefacts with 20–40 half-widths of duct
   and calls domain-length tests mandatory; no code publishes one.
5. **Ni et al. 2007 Part I §4.4** [P]: the fringing example (Ha 100, Re 200,
   domain 40 × 2 × 0.4, field eqs. 87–88) shows current streamlines and pressure
   traces only, with no reference values, and "upstream does not correspond
   exactly to a fully developed condition". It is a structural check, not a gate.
6. **Field consistency** [Albets-Chico, Votyakov, Radhakrishnan & Kassinos, FED
   86 (2011) 5–14]: on the ALEX peak transverse pressure difference a
   `B_y`-only field under-predicts by about 16 %, a curl- and divergence-free
   field by about 9 %. LMX's `fringe_field` builds its solenoidal pair from an
   entire complex continuation (no pole in the duct), with a `B_y` jump of
   7.0 % of B0 at `|y| = 1` at the joins of the ANL profile; a field fitted to a
   measured profile should be smooth (Klüber, KIT thesis 2023, Table C.1 gives an
   analytic fit of the measured MEKKA fringe).
7. **GPU float64 on this hardware** [NVIDIA GA102 whitepaper; Lehmann et al.,
   PRE 106 (2022) 015308; Lee et al., ISCA 2010; STREAmS-2, AFiD-GPU, CaNS-GPU
   node-to-node figures]: GA10x runs float64 at 1/64 of float32 (about 0.3
   TFLOP/s on an A4000). Fair one-card-versus-one-node float64 speed-ups in
   published CFD are 1.5–4×, bounded by the memory-bandwidth ratio; claims of
   10× or more divide by one core or one socket. Hence D23.
8. **Poisson algorithms** [Costa et al., CaNS-EIGEN, arXiv:2603.09528 (2026);
   jax-cfd `fast_diagonalization.py`; Oceananigans solvers]: dense GEMM
   transforms cost 1.7× the all-FFT solve at 128³ on one CPU core in float64
   and 2.8× at 1024³ on a GB200, and scale better in parallel; production codes
   use FFT in uniform directions and a tridiagonal or dense transform in the
   stretched one. On a 1/64-float64 card the GEMM route loses in pure float64,
   but LMX's float64-accurate mode runs its contractions in float32, where the
   GEMM wins (measured, D24). Krasnov, Akhtari, Zikanov & Schumacher, JCP 474
   (2023) 111784 is the tensor-product-Thomas solver for liquid-metal MHD.
9. **Mixed precision** [Carson & Higham, SISC 40 (2018); Prusak et al.,
   arXiv:2609.19828 (2026); Karp et al., arXiv:2506.05150 (2025)]: an FP32 inner
   solve with FP64 residual correction reaches working accuracy for condition
   numbers up to about 1e8; published CFD gains are 1.7–2× on the step. Reverse-
   mode gradients under reduced precision are not studied in the literature; LMX
   checks them against finite differences.
10. **Two GPUs over PCIe** [JAX-AMG, arXiv:2606.09001 (2026), Table 3 on RTX
    A6000; jaxDecomp, JOSS 11 (2026) 8852]: a 2-GPU Poisson solve on workstation
    Ampere was slower than one GPU. Use the pair for ensembles (G5a); spatial
    decomposition only for capacity (≥ 512³).
11. **Validation data** [Smolentsev et al., FED 100 (2015) 65; ALEX, OSTI 5332375;
    Urgorri et al., PPCF 66 (2024) 015015; Mistrangelo et al. 2025]: ALEX reports
    no instrument uncertainty; ALEX reports are US-Government works and may be
    digitised and redistributed with attribution, while KIT papers of 2024 are
    CC BY-NC-ND (cite, do not redistribute digitised numbers). KIT MEKKA data
    (WCLL mock-up pressures at 28 taps, 160-pin wall potentials) are available on
    request; MaPLE (PbLi, now at KIT) has published its first-campaign geometries
    before measuring, which allows a blind prediction. GridapMHD reaches 0.22 %
    on Shercliff at Ha 1000.
12. **Novelty and what is already published** [Àlvarez-Hostos, Urgorri &
    Principe, CMAME 452 (2026) 118787]: adjoint topology optimisation of fully
    developed duct cross-sections exists, so "MHD design optimisation" is not new.
    Not found anywhere: an end-to-end differentiable inductionless blanket-duct
    solver, an open or differentiable core-flow solver, a differentiable
    non-periodic fringing solver with imposed flow rate, and a machine-checkable
    benchmark-acceptance record.
13. **Why varying fields are slow** [Lee, Wu, Xu & Zikatanov, M3AS 17 (2007);
    Bhattacharjee, arXiv:2608.30265 (2026)]: the Lorentz term acts as a penalty
    of size about Ha² whose kernel, within divergence-free fields, is the
    core-flow space (fields whose electromotive force is a potential gradient),
    about one mode per field line. A subspace-correction preconditioner is
    robust in the penalty only if it captures that kernel: the uniform
    field-line solve does (13–49 CG iterations measured), the damped fallback
    does not (1,454 at Ha 100 on a 16 × 24 × 24 fringe), and a partial capture
    for one component did worse (#150). No published preconditioner is shown
    Ha-robust for inductionless MHD in a varying field; GridapMHD falls back to
    MUMPS and calls it open (Urgorri et al. 2024). A two-level method with a
    physically motivated coarse space is the evidenced route (Tang et al. 2009,
    A-DEF2; Vasilyeva, Wimmer & Southworth, arXiv:2412.08355: O(1) two-grid
    iterations to anisotropy 1e12 with field-aligned coarse spaces); using the
    core-flow model as that coarse space has no prior art (2b.4).
14. **The round-off floor** [van den Eshof & Sleijpen, SIMAX 26 (2004); van der
    Vorst & Ye, SISC 22 (2000)]: an inexact operator application caps the
    attainable CG accuracy; in the core J = σ(−∇φ + u×B) is a small difference
    of large terms, so a potential solve inconsistent with the face stencil is
    amplified by about Ha². Refining the potential solve and replacing the
    recursive residual address the cause (2b.3); s-step and pipelined CG would
    make it worse (Cools et al., SIMAX 39 (2018)).
15. **Cheaper derivatives** [Stathopoulos & Orginos, arXiv:0707.0131; Parks et
    al., SISC 28 (2006); Carter, SISC 14 (1993); Kouri & Ridzal (2018); Pierce &
    Giles, SIREV 42 (2000); Kenway et al., Prog. Aerosp. Sci. (2019)]: CFD
    adjoints cost 0.7–2.2× the primal (DAFoam 1.7–2.2×, Jacobian-free ADflow
    0.7×); LMX measures 1.6–2.1× (Section 2.5). Symmetric problems admit a free
    adjoint when the objective weight is the drive (2b.2); Krylov recycling saves
    39–50 % on later right-hand sides; inexact adjoints tied to the optimiser
    save an estimated 40–60 % of adjoint iterations (2b.6).
16. **Compilation** [JAX documentation on closed-over constants; issues #14655
    and #29684]: closed-over arrays become compile-time constants that XLA tries
    to fold, which is slow, and they key the persistent cache, so every new field
    misses it. Passing the problem data as pytree leaves compiles once per shape
    (2b.1); measured on 2026-09-22, a new Hartmann number on the same mesh
    recompiled in 15 s while the same change through a traced argument cost 29 ms.
17. **GPU while-loops and batching** [JAX discussion #32791; Rupp et al., ACM
    TOMS 43 (2016)]: small linear solves on a GPU are kernel-launch bound;
    batching independent solves with `vmap` fills the card at close to linear
    throughput, and sequential scans (the banded line solve) should become
    batched dense products where memory allows (2b.7, 2b.11).
18. **Sparse direct solves for 2-D problems** [spineax, cuDSS for JAX,
    arXiv:2606.26341; JAX discussion #18452]: nested dissection factors a 1e5
    2-D system in under a second with no round-off floor, and a symmetric
    factorization serves the adjoint; `jax.experimental.sparse` is not
    differentiable (2b.8).

Each decision records the context, the decision, its consequences, and the
reviewer's reconciliation of #64/#65/#66. New decisions go to `docs/adr/`.

**D1. One new 3-D core on the Ni/MAC/fast-diagonalisation recipe.**
Context: the generic recurrence is Stokes-like, clipped and unconverged; the B2
lane is closer to Ni's scheme but collocated, tuned per benchmark and unconverged.
Decision: write `lmx/core3d` (Section 5) from the recipe in 3.1–3.2. Before
committing the momentum discretisation, run #65's tiny-oracle comparison (MAC vs
repaired collocated on an 8³ problem: nullspaces, energy identity, adjoint cost,
line count) and record the result in `docs/adr/0002`; MAC is the default and the
oracle must show a reason to deviate. Reuse the B2 lane's face-current and
limited-convection pieces, the mesh/materials/IO modules and SOLVAX solvers.
Consequence: one formulation for duct and pipe; steady and transient share one
residual; adjoints by IFT; ≈ 2,000 lines replace ≈ 8,000.

**D2. Freeze the specialised B1/B2 lane now; delete it on a trigger.**
Trigger: the new core reproduces Shercliff/Hunt at Ha 1000 (Table I flow rates

middle path between #64 (delete now) and #65 (keep until replaced).

**D3. `lax.scan` time loop with per-step checkpointing; host code sees chunks.**

## 5. Target architecture

```
src/lmx/
  grid.py            Grid (static shape, spacing, offsets), Field pytree, stretched 1-D coordinates
  bc.py              pad-with-ghosts per BC kind: periodic, no-slip, insulating, thin-wall, symmetry
  ops.py             slice stencils on padded arrays: grad, div, laplacian, face interpolation
  poisson.py         FastDiag (host eigh, tensor apply), DCT path, PCG fallback via SOLVAX
  em.py              face currents J_n,f, Ohm's law, face Lorentz force, thin-wall surface Laplacian
  core3d.py          one step(state, params) -> state: predictor (CN diffusion, conservative limited
                     advection, implicit Lorentz damping correction), potential solve, projection
  timeloop.py        scan over checkpoint(step); chunked host acceptance, restart, logging
  steady.py          residual R(u,p,phi;theta); Newton–Krylov via solvax.root_solve; IFT adjoint
  fully_developed.py existing 2-D solver (from cases/solvers), thin-wall option, steady-linear response
  q2d.py             ETDRK2/4 spectral SM82 with forcing, budgets, spectra
  thermal.py         energy equation on the MAC grid, conjugate walls, Joule source (Phase 5)
  fields.py          analytic fringes (Votyakov), tabulated NPZ fields, offline ESSOS sampler
  shard.py           make_mesh(('x',)), slab sharding, ppermute halos, all_to_all transposes
  io.py, specs.py, cli.py, physics.py   as today, trimmed
```

Data model: one frozen `Case` dataclass (geometry, materials, field, drive,
walls, solver controls, dtype), one `State` pytree (face velocities, p, φ), one
`Result` (state, diagnostics, status). Names are labels; models are selected by
fields (already true after #63). Gauges follow boundary conditions and conductor
connectivity; a fixed-flow multiplier is an unknown in the equations, never a
post-hoc rescaling (#65).

Solver strategy: transient = projection step under `scan`; steady =
Newton–Krylov on the same residual with the projection step as preconditioner;
both share `em.py` and `poisson.py`. Adjoints: steady → IFT (one transposed
solve); transient → per-step `jax.checkpoint` in `scan` or SOLVAX
`checkpointed_fori_loop`. Never tape Krylov iterations.

Sharding: slab along the axial direction for the 3-D core (halo 1 for
second-order stencils, 2 with limited advection); Q2D via sharded `jnp.fft` or
jaxDecomp; both selected by `num_devices`. Design sweeps use `vmap` batching
before spatial sharding.

## 9. How we work

- **Branches and PRs.** `main` always releasable; short-lived branches; merge
  commits for integration batches, squash otherwise; ≤ 400 changed lines per PR,
  one concern, tests in the same PR; description = what, why, how verified
  (three lines) plus the plan step it advances. No per-PR evidence template.
- **Tests.** Markers `unit`, `regression`, `slow`, `gpu`, `external`. PR CI runs
  `unit` on one Python (≤ 5 min) and `regression` only for PRs to `main`
  (≤ 8 min); no coverage threshold on PRs; coverage reported at release.
  Reference data via pytest-regressions with provenance sidecars. Docs-only PRs
  run docs checks only. The PR regression lanes run the floor stack (Python
  3.10, JAX 0.6.2, SOLVAX 0.19.0), the only JAX version CI tests; a PR that
  changes numerics merges after its regression shards report, or after the
  floor stack ran locally (#151).
- **Nightly (office box, cron, never a PR runner).** `git pull main`; `slow`,
  `gpu`, `external` (FreeMHD Docker); benchmark JSON to a `benchmarks` branch;
  failures open one issue.
- **Benchmarks.** pytest-benchmark on PRs carrying a `run_benchmarks` label; asv
  history from the nightly.
- **Campaign discipline (D12).** Before any run longer than an hour: hypothesis,
  expected diagnostic change, budget, exit criterion, in the issue. A failed
  bounded attempt produces a decision. Tolerances are specified from scales,
  refinement and uncertainty before running, never relaxed to obtain a pass.
- **Planning.** `ROADMAP.md` one page (next three milestones, dates); ADRs in
  `docs/adr/` for decisions that change equations, tolerances, formats or public
  API; this `plan.md` is the logbook (D22): updated with every merged batch.
- **Size.** Architecture audit budgets follow this plan (modules ≤ 14 after
  Phase 4, source ≤ 9,000 lines, media ≤ 1 MB, clone ≤ 5 MB); no history rewrite
  unless a measured size problem appears. Until step 4.6, the line budgets in
  `scripts/audit_architecture.py` are interim ratchets set to the merged size
  plus in-flight steps that have named their lines (2026-09-13: 18,800 total and
  10,300 maintained core, after #125–#132 added 652 lines, 274 of them in the
  `cases.py` path that 4.6 deletes, and 1.7d part ii's 144). A PR that raises a
  ratchet names its plan step and the lines it adds; 4.6 resets both to the
  Phase 4 targets.
- **AI-assisted work.** Same rules; the reviewer reads the diff; CONTRIBUTING
  carries the disclosure JOSS requires.
- **Authorship.** All commits authored by the project owner; no tool attribution.
- **Critical path (D21).** At most one open PR outside Phases 1, 2 and 4 until
  1.10b and 4.6 land; no feature lands on the legacy fully developed stack.
- **Speed and derivative evidence.** A PR that touches a solver reports the
  warm forward time, the gradient time, their ratio, the CG iterations and
  the cold compile time before and after, on named hardware (Section 2.5
  is the baseline); a regression in any of them is stated, not hidden.
- **Profile before optimising.** A performance PR names the traced share of
  runtime it targets (≥ 10 %) and the measured change; a GPU number without its
  matmul precision and host load is not quoted.
- **Descriptions.** One page: what, why, how verified, plan step. Evidence is
  attached JSON and logs; handoffs update Section 2 and the log, not a new
  essay per PR.

## 10. Risks and fallbacks

| Risk | Mitigation |
|---|---|
| Office GPU unavailable for weeks | Phases 1, 3, 3b, 5, 6 are CPU-developable; Phase 2 targets slip, not the release |
| Fast diagonalisation inapplicable with explicit conducting shells | PCG fallback (D5); thin wall is the default |
| Newton–Krylov stalls at B2 | pseudo-transient continuation from the projection loop; report `external_validation_open` with numbers; no retuning campaign |
| Tiny oracle favours collocated | follow the ADR; the recipe's other parts (face currents, thin wall, fast diagonalisation, scan) are unchanged |
| B1 unaffordable | documented estimate; not a release blocker |
| Digitised data disputed | request originals; publish digitisation error; keep FreeMHD comparison independent |
| Rate limits on agent sessions | phases are split into independently mergeable steps |
| Plan drift | change only by ADR; competing drafts are closed |
| The core-flow model is wrong at B2 by its inertial error (N^(−1/3) ≈ 0.05 at N 540) | report the model error separately; the 3-D core at moderate N with continuation in N (1.9d) measures it; the 5–10 % B2 tolerance stays |
| The core-flow coarse space (2b.4) does not cut iterations | 2b.0's spectrum decides first; fall back to recycling (2b.5) and batching (2b.7), and record the negative result |
| A new optimisation lands only on one side of the floor stack (JAX 0.6.2 in CI, newer locally) | run the floor stack locally before a numerics PR (Section 9); #151 is the precedent |

## 12. Instructions for an independent agent

1. **Before touching code**: `git fetch`; read `ROADMAP.md`, this Section 6 for
   your phase, and the ADRs; check open PRs and the nightly `benchmarks` branch;
   never work in another session's checkout (use a worktree).
2. **Pick the next unblocked step** in the dependency graph; open an issue with
   the step ID, the hypothesis, the budget and the exit criterion.
3. **Implement in one PR per step** (≤ 400 lines). Tests in the same PR. Run
   `python scripts/run_full_test_suite.py --changed-from origin/main` locally
   before pushing. Docs and the gallery entry ship with the step.
4. **Claim only what the gate measured.** The PR description quotes the numbers
   against the exit column and the validation rows; "implemented" alone is not
   a claim.
5. **Costly runs** (Docker, GPU, refinement) go to the nightly job or a labelled
   benchmark run, never to PR CI.
6. **When a step fails its gate**, write the numbers in the issue, decide
   (continue with a new bounded budget, change the operator via an ADR, or stop),
   and record the decision. Do not retune benchmarks to pass.
7. **Every merged batch** (D22): update Section 2 with the measured state, mark
   the step done with its PR in Section 6, add the log row below, and put the
   handoff (what, why, how verified, plan step, next step) in the PR description.
8. **Commits and PRs are authored by the project owner**, with no tool attribution.
9. **After the #122 privacy rewrite, use a fresh clone; do not merge
   pre-rewrite ancestry back.** Old commit identifiers in discussions are
   evidence, not checkout bases.
10. **Read Section 2.5 and the latest "Order of work" block (2026-09-22) first.** The next
    unblocked step is there; a step outside it needs the D21 exception stated
    in the issue.
11. **Speed and derivative claims** quote Section 2.5's protocol: warm forward,
    gradient, ratio, iterations and cold compile, before and after, on named
    hardware with the host load; run the JAX 0.6.2 floor stack locally before
    pushing a numerics change.
